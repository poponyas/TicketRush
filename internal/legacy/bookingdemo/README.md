# Первое упражнение: конкурентное бронирование в памяти

Здесь сохранены исходные handlers, модель и тесты на 100 запросов/20 билетов.
Они не подключены к основному серверу и не используют новую модель Event/Session/TicketType.

```sh
go test -race ./internal/legacy/bookingdemo/...
```

Бронирование продуктовой версии будет отдельной фичей с PostgreSQL-транзакциями,
истечением удержания и идемпотентностью.
